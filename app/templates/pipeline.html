{# Deeper learning content -- the stage-by-stage tour #}
📘
Deep dive

What really happens behind each stage

1. Code & Commit

  • Branch from main.
  • Pre-commit hooks: lint, format, basic checks.
  • Small, focused commits with clear messages.
  • Open a Pull Request to trigger CI.

2. Build

  • Install dependencies (pip, npm, maven…).
  • Compile sources / transpile JS / TS.
  • Package artifact (Docker image, jar, wheel).
  • Push to artifact registry with a unique version tag.

3. Test

  • Unit tests (fast, isolated).
  • Integration tests (DB, queues, services).
  • Security scans (SAST, dependency CVEs).
  • Coverage and quality gates.

4. Deploy

  • Promote to staging, run smoke tests.
  • Blue/green or canary roll-out to production.
  • Health checks, alerts, automatic rollback.
  • Tag release in source control.
{# Best practices #}
Best Practices

10 habits of healthy pipelines

  1. Keep main always deployable.
  2. Commit small, review often.
  3. Make every step idempotent – running twice should be safe.
  4. Fail loudly and fast – stop the pipeline at the first red flag.
  5. Use infrastructure as code (Terraform, Ansible) for environments.
  6. Cache dependencies between runs to keep CI fast.
  7. Run security scans on every PR, not once a quarter.
  8. Treat flaky tests as bugs – fix or quarantine immediately.
  9. Automate rollback. Never recover by hand under pressure.
  10. Observe everything – metrics, logs, traces – from day one.
